# Research methodology

## Research question

Given only a questioned audio file (and optionally a reference), which *technical*
observations about its editing, encoding and resampling history can be established, how
strongly do independent observations agree, and what remains undeterminable?

## Principles

1. **Separate observation from interpretation.** Every finding has a category:
   `observed` (directly measured: bytes, exact sample values, header fields, a verified
   waveform match), `statistical` (unusual relative to this file's own baseline),
   `explanation` (generated by correlation rules) or `undetermined`.
2. **Independence before corroboration.** An edit point is *corroborated* only when
   detectors built on different physical principles agree (waveform continuity, background
   noise, digital silence, mains-hum phase, duplication, quantisation). Detectors that are
   mechanically implied by another observation (a noise-floor drop caused by inserted
   digital zeros) or that fire on ordinary content (energy/spectral jumps, all Module F
   statistics) never count.
3. **Ordinal indicator levels, no probabilities.** Levels follow published rules
   (`evidence/assessment.py`). Thresholds come from signal-processing reasoning, checked on
   the calibration split only.
4. **Alternative explanations are mandatory.** Every finding lists legitimate processes
   that produce the same signal, and every report lists what cannot be concluded.
5. **Forensic integrity.** Evidence files are opened read-only, hashed (SHA-256) before and
   after analysis; FFmpeg decoding writes to a private temporary directory; analysis is
   deterministic; resource limits (512 MiB, 600 s, 16 channels) fail loudly.

## Pipeline

| Module | Content | Tests |
|---|---|---|
| A File structure | magic-byte sniffing; binary parsers for RIFF/WAVE/RF64, MPEG audio (ID3, Xing/Info, LAME tag), FLAC (STREAMINFO + PCM MD5 verification), Ogg (page CRC-32, sequence, chaining), MP4 (box tree, mvhd times, ilst), ADTS, AIFF; FFprobe metadata; software signatures | A1, A2 |
| B Signal | RMS, peak, true peak, ZCR, crest factor, DC, clipping, STFT, centroid, bandwidth, roll-off, flatness, flux, mel/MFCC, LTAS, band energy distribution, noise floor | (descriptors) |
| C Splicing | LPC-residual impulses, energy and spectral discontinuities, noise-floor consistency, digital silence/padding, duplicated segments, ENF phase | C1-C7 |
| D Compression | band limit, spectral holes, bit depth and histogram combing, codec lowpass/bitrate consistency (LAME tag, or a measured libmp3lame low-pass model when the tag records none), explicit statement that generation count is undeterminable | D1-D4 |
| E Resampling | empty band below Nyquist with candidate source rates, interpolation periodicity (experimental), sample-rate metadata consistency | E1-E3 |
| F Statistics | robust z/MAD, Isolation Forest, PELT, KS windows, delta-BIC | F1-F5 |
| G Correlation | temporal event clustering with independence rules, file-level processing-history assessments, indicator levels, false-positive considerations, cannot-conclude list | - |

`compare` adds a controlled reference comparison: block-wise NCC alignment against a
reference, reporting offset steps (removed/inserted material), unmatched blocks, gain
changes and bandwidth differences.

## Experimental design

* **Dataset** (`sonictrace dataset generate`): synthetic sources (formant-synthesised
  speech-like signals and harmonic music-like signals with jitter/vibrato/random phases)
  in four background environments (room/pink, mains hum 50 Hz with ENF drift, street/brown,
  quiet), always with a white self-noise floor, quantised to 16-bit with TPDF dither.
* **Conditions per source (17-18)**: clean; added background noise; hard cut; cut with
  10 ms crossfade; inserted digital silence; gain step (+6, +4, -4.4 or -6 dB, undithered);
  copy-overwrite; background-environment splice; resampling (polyphase down/up, linear-
  interpolation up, 44.1 -> 48 kHz); MP3 64 kbit/s (1 generation), 64 -> 96 kbit/s
  (2 generations), 64 -> 192 kbit/s stored as MP3 (transcoded); legitimate processing
  probes: peak normalisation, hard noise gate, loop-based music (tonal sources).
* **Controls**: 4 extra unmodified recordings per split (incl. a native 48 kHz and a quiet
  recording).
* **Splits**: 4 sources + 4 controls per split; sources never shared between calibration
  and evaluation; all randomness from `default_rng([seed, split, source, purpose])`.
  Default seed 1337 -> 140 files (70 + 70).
* **Ground truth**: `manifest.json`/`manifest.csv` with labels (`edited`, `edit_type`,
  `compressed`, `compression_generations`, `resampled`, `gain_edit`, `duplication`,
  `legit_processing`), edit times and a per-file transformation log and SHA-256.
* **Scoring** (`sonictrace benchmark`): each technique against the label it targets, on
  *all* files of the split (so legitimate processing counts as negatives); precision,
  recall, F1, FPR, confusion of the local-edit level vs. `edited`, per-condition detection
  rates, localisation within 0.15 s, threshold sweeps x0.5-x2.0 of the primary score.
* **Procedure**: methodology v1.0 run on calibration -> false-positive investigation
  (research/false_positive_analysis.md) -> v1.1 changes justified by calibration
  evidence -> final run on calibration and evaluation. Evaluation results were not used
  to change anything. v1.2 changed only D4 after a gap was noticed on one evaluation file;
  the fix rests on a separate noise measurement (`experiments.md`, E4).
